### Niezaliczona bramka authenticated auth/proxy

`check-proxy-public.py` zatrzymał się na pierwszym logowaniu: **HTTP 401**
zamiast 204. Dalsze kontrole zalogowanej sesji/sync, cookies, Origin/CSRF,
logout i publicznego spoofed-XFF nie zostały wykonane. Jedna nieudana próba;
brak utworzonej testowej sesji. Nie ponawiano logowania i nie resetowano hasła.

Diagnoza wyłącznie odczytowa potwierdziła, że hasło z `initial-account.txt`
nie pasuje do konta. Kontrola danych users z predeploy dumpa w pamięci
(`pg_restore --file=-`, bez odtwarzania DB) dowiodła, że **nie pasowało także
przed promocją**, a hash konta jest identyczny przed/po. Emitowano tylko
wartości logiczne, nigdy hasło/hash/token. Potwierdzenie: **09:56:42 UTC**.

To preexisting problem credentials historycznego smoke, nie wykazana regresja
logowania. Pozostaje ręczna/ponownie zlecona akceptacja z aktualnymi danymi
operatora. Nie obchodzono uwierzytelniania. Health jest poprawny;
**rollback nie był wymagany ani wykonany**, ale pełnej akceptacji auth nie ma.

i sender (ich obrazy przed wydaniem były różne). Wyłącznie po decyzji rollback:

```bash

  docker compose -f /docker/fit/compose.yaml -f /docker/fit/compose.push.yaml -f /docker/fit/compose.mentor.yaml "$@"

docker tag fit-web:rollback-1.14.0-27-web-20261017T095357Z fit-web:production
dc up -d --no-deps --no-build --wait --wait-timeout 180 web
docker tag fit-api:rollback-1.14.0-27-api_running-20261017T095357Z fit-api:production
dc up -d --no-deps --no-build --wait --wait-timeout 180 api
```

Nie odtwarzać produkcyjnej DB automatycznie. Stary backend nie zapewnia nowej
ochrony omission; działające starsze/nowe klienty z cache i zapisane rozszerzenia
wymagają oceny ryzyka przed planowanym rollbackiem. Backup pozostaje punktem
odzyskiwania danych, a nie poleceniem ich nadpisania.
