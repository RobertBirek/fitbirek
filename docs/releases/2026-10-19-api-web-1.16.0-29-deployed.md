## Jawne rozstrzygnięcie MIME

Nowa kontrola po wdrożeniu zgłosiła sześć TTF z `application/octet-stream`
zamiast oczekiwanego `font/ttf` — pięć wag Inter i CupertinoIcons. Pierwotny
FAIL `BLOCKED_MIME` pozostawiono w dowodach; nie zmieniono asercji ani logów.

Następnie uruchomiono stary zachowany web1.15 w odizolowanym kontenerze,
`--network none`, bez portów. Jego rzeczywiste odpowiedzi dla wszystkich sześciu
fontów miały ten sam MIME, HTTP200, `no-cache`, identyczne bajty/długości/SHA.
Konfiguracje Nginx i `mime.types` obu obrazów są identyczne. Fonty mają
prawidłowy nagłówek TrueType i tabele, nie są zastępczą odpowiedzią HTML.

Flutter3.35.4 CanvasKit pobiera te fonty jako bufor bajtów, nie jako arkusz CSS;
wcześniejsza akceptacja dokładnego runtime potwierdza czytelny UI online/offline.
**Klasyfikacja końcowa: nieblokująca wcześniejsza niedokładność metadanych,
nie regresja wydania.** Mapowanie `font/ttf` pozostaje osobną poprawką do
wersjonowanego wdrożenia. Nie zmieniano produkcji ani nie osłabiano `nosniff`
w celu obejścia kontroli. Kontener porównawczy został usunięty.
