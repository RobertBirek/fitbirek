## Instrukcja aktualizacji istniejącego profilu

Jeżeli nowa wersja pokaże blokadę **schemat12, wymagany13**:

1. **Nie usuwaj danych witryny/aplikacji, cache, IndexedDB ani oczekujących zmian.**
2. Nie próbuj obchodzić blokady deep linkiem ani wymuszać zapisu ze starej karty.
3. Zamknij **wszystkie** karty/okna FitBirek, **także zablokowane nowe okno/PWA**,
   i wykonaj normalne pełne wyjście z przeglądarki, aby zakończyć jej proces
   i współdzielone połączenia. Samo zamknięcie starej karty nie jest sprawdzoną naprawą.
4. Uruchom przeglądarkę ponownie z **tym samym profilem** i otwórz FitBirek.
   Sprawdzona ścieżka pozwala wtedy wykonać addytywną migrację przed auth/router/sync.
5. „Spróbuj ponownie” to tylko kontrola zgodności, **nie restart połączenia**.
   Przy przyszłym schemacie14 użyj aktualniejszego klienta, bez downgrade DB.

Pełne zamknięcie procesu zostało sprawdzone w izolowanym Chromium, nie na każdym
desktop/mobile/PWA. **Fizyczny iPhone/Android, background/storage retention,
uniwersalne zamykanie PWA: manual pending.** Nie deklarujemy live auto-migration,
niezależności od procesu przeglądarki ani zero-warning VS16/dowolnego Unicode.

docker tag fit-api:rollback-1.15.0-28-api_running-20261018T134618Z fit-api:production

nie wymuszać lokalnego downgrade ani czyszczenia danych. Backup jest punktem DR,
nie automatycznym poleceniem nadpisania produkcji.
